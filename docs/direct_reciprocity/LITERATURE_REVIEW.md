# 直接互惠中的代码策略演化：反馈收益与合作泛化的区别

## 摘要

本调研面向当前 LLM 策略生成框架的直接互惠分支。以用户指定的三篇研究为起点，结合代码生成、自博弈与 IPD 评价文献，区分提示词操纵、搜索/选择机制及博弈内观测。文献支持代码生成和绩效反馈是可操作的研究路线，但已有实验改变的不仅是提示词，还包括策略表示、对手信息和选择对象。训练锦标赛收益、合作率与演化稳定性不是同一指标。新实验应采用完整收益矩阵与双边历史，在固定默认锦标赛参数下分离提示词与选择机制，并用保留对手及噪声/长度变化评价泛化。

## 1. 研究问题与范围

RQ1：固定接口、模型与评价条件，反馈提示词能否提高生成策略的收益及合作表现？RQ2：相同变异算子下，选择规则如何影响改进和多样性？RQ3：训练收益提高能否推广到未参与生成的对手及环境？本调研关注 LLM 生成可执行策略，直接动作输出研究仅用于识别测量混淆。具体证据与章节见 CSRO_LITERATURE.md 和 COOPERATION_LITERATURE.md。

## 2. 检索与核实

2026-09-15至16日，读取用户本地9页 PDF；分三个视角检索代码 oracle、合作提示词及反证、经典 IPD 评价。采用 arXiv、会议官方全文、期刊发表页及作者仓库。当前会话 Zotero 不可调用，两篇指定研究使用公开原文。检索词包括论文完整题名、LLM code policy / PSRO、IPD prompt framing、tournament noise generalization。逐项区分摘要证据、全文细节与推断，不把模型语言说明当作策略行为证据。本文不是穷尽式元分析。

## 4. 生成与搜索：代码可读性不等于最优性

Li与Wang的代码锦标赛将同代与历史对手收益反馈给生成器，以排名截断更换群体的一半；CSRO则围绕元策略混合生成响应，并在内部精炼候选。前者更接近本任务的 IPD 环境，后者更清楚地分离外层对手分布和内层代码改进。CSRO的实证对象为零和 RRPS/Leduc，其负收益触发准则不能直接搬到收益非负的经典 IPD。LLM-PSRO使用 best-of-N，可作为无反馈采样的机制参照。以上研究均不能仅据可读代码认定注释忠实或策略稳健。[CSRO原文](https://arxiv.org/html/2603.10098v1)；[LLM-PSRO官方论文](https://www.ijcai.org/proceedings/2025/1249)。

本地论文明确 N=12、每代淘汰6、10代、5种子、温度1.0、R/S/T/P=3/0/5/1、同代与HoF权重0.6/0.4、每代前三入档。每场100轮只能由分数提示推定，重复次数与归档去重未明确。必须将这些工程约定列出，避免宣称逐项精确复现。详见 RESEARCH_BRIEF.md。

## 5. 提示词：行为目标与绩效反馈需要拆分

Willis等比较 attitude 与 Default/Refine/Prose，说明提示可以改变生成策略的表现；其 Moran 过程选择 attitude集合，每场再抽一条策略，并非持续改写个体算法。因此该演化结论不能直接验证新框架中的代码优化机制。Phelps与Russell显示 persona 与措辞会影响直接动作输出；相比之下，open-source games允许运行时读取对手代码，改变了游戏的信息结构。这些差异要求新实验固定双边历史接口，将训练时给生成器对手代码和运行时策略读取对手代码严格区分。[Willis完整论文](https://arxiv.org/html/2501.16173v1)；[Phelps与Russell](https://arxiv.org/html/2305.07970v2)；[Open-source games](https://papers.nips.cc/paper_files/paper/2025/file/9649863f655babbe8102b84726eb2829-Paper-Conference.pdf)。

## 6. 评价：高合作率未必意味着高适应度

经典 IPD 大规模锦标赛研究发现性能依赖对手构成、噪声及长度，小型固定对手集不足以支持普遍稳健。Nicer than Humans又显示历史窗口改变可引起明显行为差异，说明合作率可能混入上下文处理问题。代码策略能减轻逐轮LLM调用的上下文成本，但仍需验证策略只使用自身对局历史、错误不被静默替换为合作/背叛、每个条件采用相同评价种子。[Glynatsi等](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1012644)；[Nicer than Humans](https://ojs.aaai.org/index.php/ICWSM/article/download/35829/37983/39897)。

## 7. 综合判断与未解问题

可识别的研究重点是“在同一代码策略空间中，提示反馈与选择规则的主效应和交互”，而非预设某种方式最合作。全文反馈可能带来更多信息和token成本；Fermi可能产生更少接受事件；HoF会随路径改变。等代数的整套流程效果与等调用预算的搜索效率应分别报告。保留对手必须在生成前固定，禁止将其成绩用于挑选最终策略。当前证据不足以预先判断哪种组合获胜。

## 8. 对研究问题的回答

RQ1：已有研究支持提示可影响策略，但效果受模型、反馈量和表示约束，需受控比较。RQ2：原框架把选择和变异绑定，应先固定变异再比较选择，原样组合仅作补充。RQ3：训练HoF提高不足以证明泛化；必须报告独立测试收益、合作率、最差对手表现和跨种子不确定性。本任务以此冻结以下实验方案，再实现运行。
