# 直接互惠实验方案 v1

冻结时间：2026-09-16，文献调研完成之后、实验代码实现之前。研究问题和证据见 LITERATURE_REVIEW.md。此为受控研究实现，不宣称原论文逐参数复现。

## 默认锦标赛

- N=12；10次群体评价（g=0..9，9次更新）；每次替换6条；5种子0..4；生成温度1.0。
- 完整 R=3,S=0,T=5,P=1；每场100轮、重复5次、无自我对局、默认无噪声；所有轮累计分数，按对手与重复平均，fitness=0.6 peer+0.4 archive。
- 100轮、5重复、无自我对局、10次评价的计数和初始无噪声是本项目明确约定，不是全部原文已报告值。
- 固定13种训练基线：ALLC, ALLD, TFT, Grim, Pavlov, Random, Alternator, Bayesian, GTFT, Gradual, Prober, SuspiciousTFT, Extort2。Bayesian等存在变体，代码与参数写入输出，不声称等于作者私有实现。
- 每代评价结束后前三入HoF；按代码hash去重；新档案仅用于下一代。固定基线成绩和动态HoF成绩分别保存。
- 每场只允许两方动作历史，不提供第三方行为、身份或对手源码。采用 strategy(history, rng) -> 'C'|'D'；history为只读的(自身执行动作,对方执行动作)序列；rng为该场该策略独立随机流。与论文签名差异仅为可重放随机源。

## 主实验与对照

提示词三种：minimal（游戏+父代，统一要求改进）；score（加入父代/对手分数）；full（加入群体代码与分数）。目标始终为累计收益最大化，不在主实验中同时改变合作persona。独立初始化使用同一minimal模板；每种子共享初始12条代码，所有条件同源。

选择三种：paper_truncation（前6存活）；tournament（复用框架elite=2,tournament_size=3）；fermi（复用框架快照选择，beta=1/100，使累计分差按每轮归一尺度进入logistic）。三者后续候选都用同一full变异模板、禁止独立初始化概率混入；保留未接受者。Fermi每代尝试12个不同learner，实际接受数记录，不强行声称与每代6次替换等预算。

完整主矩阵3×3×5=45条轨迹；初始12次调用按种子共享。每代记录累计请求数、token数和成功子代数，以匹配预算区间比较曲线；等代数端点称为流程效果。每种子增加独立采样对照：相同累计候选数、无绩效反馈，按训练fitness选优；若API资源受限，主矩阵优先，对照未完成需明确报告，不能声称完成全部计划。

## 独立评价

预先固定未见对手：TF2T、HardTFT、ContriteTFT、WinShiftLoseStay、随机合作p=0.2/0.8、周期CCD、AdaptiveTFT。源码不进入生成反馈。分别评价默认100轮无噪声、100轮1%噪声、200轮无噪声。测试种子独立于训练；同一测试配置所有条件共享随机种子设计。

每代训练最优策略由训练fitness唯一确定（hash破同分），再做独立评价，测试不影响下一代。报告每轮平均收益、合作率、最差对手平均收益、代码hash多样性和行为多样性。总体不把合作率当适应度、不从有限测试推导ESS。

## 可复现与异常处理

JSON保存完整配置及hash、源码、生成提示/响应、请求模型与实际返回模型、API usage、父子关系、评价种子、程序错误。独立初始化与每次请求落盘，恢复不得重复已成功请求。API失败与代码无效分开记录；不默默用基线替代LLM策略。无效候选记录并保留旧个体；初始不足12条则停止该种子，修复后复用已成功记录。运行时非法动作/超时使该候选无效，不将局部失败计为正常博弈结果。

## 分析及完成标准

先验证收益四格、TFT/ALLD解析累计值、随机流与噪声、history隔离、HoF更新、选择规则、断点恢复、失败可见性；再真实LLM小规模试运行，随后主矩阵。统计单位为独立生成种子，报告配对差值和bootstrap区间；5种子视为探索性，不以对局轮数扩大样本量。结果归档必须含全部条件状态，失败条件不能悄悄排除。

完成需要：研究调研、冻结方案、隔离worktree、测试通过、真实主实验及采样对照、原始日志和分析报告均可查。若服务/预算阻塞，保存准确状态及缺失条件，不标记整体完成。

## 独立采样对照的实现细则（主矩阵开始后、对照运行前）

对照不改变主矩阵。每种子共享初始12条；额外候选只用独立初始化提示生成，不接收父代或成绩反馈。生成到该种子9个主条件中的最大实际请求数，较低预算条件使用相应前缀；无效候选仍消耗请求预算。每个条件终点用其冻结的同代群体与当时HoF对独立池候选评分，候选替换训练冠军槽位，使用相同对局随机流。只以此训练分数选池内冠军，再用相同独立测试协议比较。该对照隔离的是条件化提案相对于独立提案的价值，保留训练环境条件化选择；不声称重现独立采样自身的群体演化。匹配请求数，不匹配tokens或评价计算量。仅做终点对照；主矩阵保留逐代预算曲线。

## 初始无效候选的恢复规则

主矩阵seed0首次在initial-2遇到违反明确接口约束的顶层import而停止。保留原始响应为initial-2.invalid-attempt0.json；在未读取该策略绩效的前提下，以相同提示重新抽样，仅修复初始化可执行性。每个初始槽最多3次额外抽样，全部请求计入预算，所有条件继续共享最终同一初始群体；不手工删import或修改生成策略。此为生成后接口筛选，报告时说明其存在，不能称无筛选纯模型分布。

## 用户修订：允许 random 导入

按用户明确要求，策略执行接口允许random导入，而不再因其存在判无效。导入随机源接入场次独立种子；不改变动作历史与收益定义。原始响应的有效性需要用新检查协议重新核实，旧批次结果保持独立。该用户要求覆盖v1方案中“禁止imports”的约定。

## 新规则批次的初始响应复用

主实验v2只复用v1中的初始生成响应，不复用任何旧收益、子代或世代状态。每个槽按原始请求时间查找最早通过新规则的响应，保留原始prompt、content、fingerprint与usage，并附源文件SHA256、原始有效性状态及reused_from。不把旧prompt伪装成新请求。所有提示×选择条件共享同一初始池。已有初始模板曾写禁止import、但模型仍输出import，这是模型初始条件的一部分；后续新生成模板允许random，种子级配对比较保持不变。没有可复用响应的槽才真正请求API。已停止v1的消耗单列，不重复算作v2新增API费用。

## 独立测试执行失败规则补充

观察到主实验minimal/paper seed1在holdout阶段触发既定20000指令上限，原执行器会在训练选优后直接中断整条轨迹。补充执行规则：仅将独立holdout的PolicyError记为runtime_failure，score/cooperation/worst_score为null，不补零、不替换动作、不增加预算、不回传训练；固定训练参照和训练评估错误仍中止。成功测试原样保存。此项属于观察失败后的协议修订，报告必须公开，不能声称完全预注册。

recover_evaluation.py作为独立入口，保持原core/run等训练源码及其指纹不变，每条恢复轨迹另存evaluation_recovery.json，包含原实现指纹与恢复入口源码指纹。仅恢复已停止轨迹。分析列出成功/失败数量；收益汇总及配对对比只含成功测试，须提示幸存者偏差。独立采样对照采用相同测试失败规则。原始失败与诊断证据保留。
